# Simulacrum Automation Builder — 0.1.0

First release of the Ebonhawk fork. Upstream's generalist campaign-assistant prompt is replaced with an automation-builder domain prompt, the provider layer is reduced to OpenRouter, and three tools are added.

## How it works

Paste an ability description into the sidebar. The agent:

1. **Parses** it into a spec — trigger, save ability, DC, range, targets, outcomes on success and failure, duration, uses.
2. **Previews** it as an editable form so a misreading is corrected before anything is written.
3. **Builds** the item: a dnd5e Feature with its save activity, damage, applied effect, and the midi-qol / DAE / CAT flags behind them.
4. **Tests** it against the token you have targeted — forcing the save to fail, then to succeed — and reports one line per claim from the spec.

## Tools

| Tool | Purpose |
|---|---|
| `preview_spec` | Presents the parsed ability as an editable form. Writes nothing to the world. |
| `build_save_ability` | Creates or updates the Feature. Idempotent by `system.identifier`, so rebuilding corrects rather than duplicates. |
| `test_ability` | Runs the ability twice with forced outcomes against your targeted token and reports a checklist. |

## Design notes

- **Edits never round-trip through the model.** The preview stashes the spec under a token and the builder reads it verbatim, so what you confirm is what gets built. Tokens are single-use, so a rebuild needs a fresh preview.
- **The preview form is authored by the agent, not templated.** A form drawn from a closed vocabulary can express a fails-by-5 clause or a repeat save without new UI code. The form is data, never markup; `showIf` is evaluated without `eval`.
- **Unknown spec keys are warnings, not errors.** If a description carries a nuance no field expresses, it is preserved and reported rather than silently dropped.
- **Tests force the outcome.** `flags.midi-qol.fail.all` / `success.all` make the run deterministic. A test that depends on dice reports false failures about half the time.
- **A claim that could not be observed reports as untested**, never as passing.
- **The test target is the token you targeted** — never one created for the purpose, which would change what the test proves. Teardown is unconditional, so a failed test leaves nothing altered.
- **Four dnd5e details are load-bearing** and each is easy to get wrong: a save activity applies its effects to failed saves only (except entries flagged `onSave`); the save DC is computed from the activity's range, never its target; a fixed DC is `dc.formula` with an empty `dc.calculation`; and `save.ability` is a `SetField`, so it takes an array.

## Requirements

- Foundry VTT 13+ (verified on 14)
- **dnd5e 5.3.3** — this release targets the 5.3.3 API and is not written against dnd5e 6.x
- `midi-qol`, `dae`, `cat` (required); `chris-premades`, `dfreds-convenient-effects` (recommended)
- An **OpenRouter API key**

## Install

Paste into **Setup → Install Module → Manifest URL**:

```
https://github.com/Ebonhawk3829/simulacrum-foundry/releases/latest/download/module.json
```

This is a private fork, not listed in the Foundry package directory.
